# Quadami: plan

One prioritized, dependency-ordered plan, merged on 2026-10-14 from the earlier TODO ([archive/TODO-2026-10-14-pre-merge.md](archive/TODO-2026-10-14-pre-merge.md)) and every research report in [research/](research/).
Update this file and add a session file in [sessions/](sessions/README.md) every session.

**Keys.** Status `[ ]` open, `[~]` in progress / partly done, `[x]` done, `[-]` deferred or dropped by a decision (reason given). Everything known but deliberately not done, with why and what unblocks it: [Parked](#parked-known-but-not-done). Item IDs (e.g. **3.3**) are wave.number; "needs" lists hard dependencies. Issue IDs P*, M*, F* are in [REFERENCE.md](REFERENCE.md); SQ-* in [SPECIALIST-QUESTIONS.md](SPECIALIST-QUESTIONS.md). Effort: S days, M 1–3 weeks, L 1–3 months. **License flags** ([LICENSES.md](LICENSES.md) §2): `OK-MIT` own or permissive code, can also go upstream; `OK-GPL3` needs a GPL-compatible dependency; `GPL3-ONLY` pulls in GPL-3.0-only code (CoMISo), **excluded by 0.2**; `ASK` no license, needs author permission or a re-implementation; `NO` never ship.

**Rules.** Upgrade, don't rewrite, unless gate 7.1 says otherwise. Change one stage at a time behind its interface (FrameField, SingularitySimplifier, QuadParameterizer, MixedIntegerLeastSquares, QuadExtractor), and A/B every change on the corpus with the Wave 1 metrics. Keep `OK-MIT` fixes in separate commits free of GPL code, so they can still go upstream if 0.5 is ever picked up.

## Order at a glance

```
Wave 0  decisions ──────────────────────────────────────────────────────────────┐
Wave 1  build · corpus · metrics · baseline (measured: REFERENCE §4.1)          │
   ├── Quick wins, any time: 8.0 tbbmalloc · 8.7 local cancelPair · 2.11 count  │
   │             fix · 2.12 boundary capping                                    │
   ├── Wave 2  diagnostics (2.1–2.4) → cheap correctness fixes (2.5–2.14)      │  Track G: Blender layer,
   ├── Wave 3  solver interface (3.1–3.2) → greedy rounding, M1 Stage A (3.3)   │  in parallel throughout
   │             → lattice/elimination fixes → measure (3.7) ── gate 7.1        │
   ├── Wave 4  sizing field (4.1) → field energy/MBO (4.2–4.3) → size into      │
   │           param (4.5) → count controller (4.7)       [parallel to Wave 3]  │
   ├── Wave 5  features → symmetry → exact count → hard guides  [needs 2.5, 3.3]│
   ├── Wave 6  extraction: libQEx A/B → cleanup worklist         [needs 3.3]    │
   ├── Wave 7  gate → Stage B quantization; singularity research; finer field   │
   └── Wave 8  performance backends            [needs 3.1 and baseline numbers] ┘
```

Critical path: **1.4/1.6 → 2.1–2.2 → 3.2 → 3.3 → 3.7 → 7.1** (3.1 left the path on 2026-10-19: 3.2 and 3.3 were done without it). Most quality items (features, symmetry, hard guides, extraction swap) wait on 3.3 because they add integer constraints that one-shot rounding collapses (REFERENCE M1, §7).

The baseline (REFERENCE §4.1) confirms this order. UV flips occur in every run and predict both cleanup time and final irregularity. It also adds quick wins that need nothing else first: 8.0 (1.22–1.54× faster, identical output), 8.7 (up to 42 % of a run), 2.11 (the quad count is 2–3× under target by default) and 2.12 (open boundaries get capped). Status 2026-10-19: 8.7, 2.11 and 2.12 are done. 8.0's gain is gone since libQEx (2026-10-22, see 8.0).
