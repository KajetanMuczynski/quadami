# Quadami 0.1.0 release notes

The hand-written part of the 0.1.0 release notes; `ci/release.py` puts it into
[TEMPLATE.md](TEMPLATE.md). A `v0.1.0` tag fails while this file holds a placeholder (`ci/release.py` looks for the word). Each claim here must be
true of the tagged commit: update it in the release PR (docs/RELEASING.md, step 3).

## What changed

First public release of Quadami, the Blender add-on built on Jeremy Hu's AutoRemesher 1.2.0. It is
a first release with known limits, not a stable one: read *Known limits* below before relying on it.
Compared with AutoRemesher:

- A Blender 4.2+ extension: panel in the 3D Viewport sidebar (**N**, tab **Quadami**). The remesher
  runs in its own process, so Blender stays usable, **Esc** cancels and a crash cannot take Blender
  down. Modifiers are used as shown in the viewport; the original object is hidden, never changed.
- A quality report after every run: quads against the target, non-quads, holes, handles, non-manifold
  edges and vertices, flipped and folded faces, empty pieces, missing parts and the time, with
  warnings that say what to do.
- Quad extraction by libQEx; a built-in fallback extractor takes over for a piece libQEx cannot
  handle.
- Thin parts survive better: pieces glued along an edge (such as vines on a blade) now go through
  libQEx too, and two clean-up passes no longer delete strips about two quads wide.
- **Repair Folds and Re-run**: detects sculpt input folded over itself (twist, rotate, pinch brushes)
  and, only when you press it, smooths those spots before remeshing. Off by default.
- Reworked rounding and untangling of the parameterization, a map check before extraction, the
  output projected onto and relaxed along the input, input cleanup.
- A build line at the bottom of the panel names the exact build; it turns red when the add-on and
  the remesher inside it come from different builds.

## Warnings in the panel

- **Holes where the input was closed**, **non-manifold** edges or vertices, **empty islands**:
  shown in red with what to try (user guide §6).
- **Handles** lost or added against the input (a ring's hole closing up, two surfaces joined).
- **Missing parts**: a part of the input (a vine, a limb, a spike) is more than three quad widths
  away from the result, so it was smoothed away or cut off; also **islands that came out with far
  fewer quads than planned**.
- **Parts thinner than one quad**: the share of the surface that is thinner than a quad, with a
  target that should fit, or the advice to thicken those parts. It states a risk: on our test sets
  most runs it fires on have folds or lost parts there, but some come out clean.
- **Folded input: N faces in K spots** with the **Repair Folds and Re-run** button.
- **Remesh to 200,000+ quads?** asks first and shows the memory it needs.

## Known limits

- **Thin parts** (leaves, vines, cloth, blade edges) thinner than about one quad can fold, lose
  pieces, or lose their handles (small tunnels close up). The panel now warns, but the fix is yours:
  raise Target Quads or thicken the part; the remesher does not yet put smaller quads on thin parts.
- **Folded sculpt input** is where most remaining defects on our test sculpts sit (about three
  quarters of them; most of the rest are on thin parts). Fold repair is off by default and leaves
  spots it cannot fix safely; folds wider than about 1 % of the model are not detected.
- **Holes** can still appear in closed sculpts, mostly next to folded input; the **Holes** row shows them.
- **A few more folded and flipped faces on thin parts than the 2026-10-22 test build (`0e9bec8`)**:
  about +5 % folded quads and +4 % flipped faces on our test sets, in the same few models on Linux,
  Windows and macOS. They sit on thin parts that test build deleted and this one keeps (the vines fix),
  mostly the sword's ribbons, the human test model and very thin closed shapes; the same change keeps
  more pieces and hits the quad count more often. Same advice as for thin parts above.
- **Thousands of tiny loose parts** (chain mail, scattered debris): every piece gets a minimum number
  of quads, so the result can have far more quads than the target (about 9.7x on a test model with
  4,888 pieces), and some pieces still come out empty (400-429 of those 4,888). Raising Target Quads
  does not help here, though the panel suggests it; merge or delete the small parts first.
- **Openings in open parts** (gums, clothes) can close, open or change shape without the **Holes**
  row counting them; it counts only holes in closed parts.
- **Sliver islands**: meshes with long, almost zero-area sliver islands (for example from boolean
  operations or scripted cuts) can take minutes and several GB of memory; use **Merge by Distance**
  and **Delete Loose** first.
- **The result keeps no UVs, materials, vertex groups, sharp edges, creases or seams.** It keeps the
  source's parent, transform, collections and smooth or flat shading, and **Remesh** on a result
  remeshes the hidden original (the panel's **Source** field).
- **Object scale**: a non-uniform scale stretches the quads; the panel warns, but apply the scale
  first (**Ctrl+A** > **Scale**).
- **Hard-surface models**: sharp edges are kept above 90°; lower angles make more triangles. No
  mirror symmetry (remesh one half and add a Mirror modifier), guide curves or density painting yet.
- **Large inputs** are slow to hand over (the mesh goes through a text file both ways).
- **Linux** has been tried by hand on one desktop (a build from before the thin-parts fixes);
  Linux, Windows and macOS all pass the automatic tests in Blender without a window.
- **Windows**: the program is not signed, so SmartScreen may warn before it first runs.
- **macOS is experimental and untested**: nobody has run this release on a real Mac, and the program
  is not notarized, so macOS may block it (user guide §2). Reports from Mac users are welcome.
- Version numbers name releases only. Test builds between releases keep this version; tell them
  apart by the build line.
