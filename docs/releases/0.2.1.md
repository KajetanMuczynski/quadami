# Quadami 0.2.1 release notes

The hand-written part of the 0.2.1 release notes; `ci/release.py` puts it into
[TEMPLATE.md](TEMPLATE.md). A `v0.2.1` tag fails while this file holds a placeholder (`ci/release.py` looks for the word). Each claim here must be
true of the tagged commit: update it in the release PR (docs/RELEASING.md, step 3).

## What changed

A fix release on top of 0.2.0, with one new button and a stricter fold count. Like 0.2.0 it is a release with known limits,
not a stable one. On all 770 runs of our standard test sets the result is the same as with 0.2.0,
quad for quad; only models of the kind in the first point below can come out differently. Compared with 0.2.0:

- **Models with very many tiny thin pieces no longer run for many minutes.** On a wrought-iron gate
  or a lace-like model, the fallback quad extraction could trace tens of thousands of quads for a
  piece meant to get about a hundred, which took many minutes or ran out of memory. Such a piece is
  now left out instead (it shows as a piece with no quads), and a later attempt at a higher count
  usually fills it. Our iron-gate test model now finishes in 9-20 seconds at 3,300 and 4,000 quads
  (12 of 12 runs).
- **Copy Report** (bottom of the result box): puts one block of text on the clipboard for a bug
  report: the build line, Blender and system versions, the run's settings, the input's size, every
  row and warning of the result box, the time of each step, the remesher's last output and the full
  report. It holds no mesh data, and your user name is removed from folder paths. It also works after
  a failed run. Paste it into the bug report form or an e-mail (user guide §6).
- **Folded faces now also counts twisted quads**: quads whose two halves face apart along either
  diagonal, which the old corner test missed. The row reads `N (T twisted)`. Quads bent along a
  sharp edge of your model (90° or more) are not counted. The mesh is the same as before; only the
  number is higher on some models (on our test sets, about 1.4 instead of 1.1 per 1,000 quads).
- **Imports marked Sharp all over no longer leave zigzag lines on the result.** 0.2.0 already left
  such marks out of Follow Marks, but **Keep from Original** still copied them, so an FBX or OBJ
  import that marks most edges Sharp got zigzag sharp paths all over the result. A mark on more than
  half of the edges of a mesh with over 1,000 edges is now not copied either.

## Warnings in the panel

- **Folded faces** includes twisted quads and shows how many of them there are (`N (T twisted)`), so
  it can be higher than 0.2.0 showed for the same result.

- **A mark on more than half of the edges is left out**: the warning now also says that the mark is
  not copied onto the result.

The other warnings are as in 0.2.0 (user guide §6).

## Known limits

As in [0.2.0](https://github.com/KajetanMuczynski/quadami/releases/tag/v0.2.0) (thin parts, folded
sculpt input, holes, hard-surface edges, the cleanup, Follow Marks, copied data, modifiers baked in,
Keep Ridges), except for the long runs on very many tiny thin pieces, fixed above. In their place:

- **Very many tiny thin pieces** (a wrought-iron gate, wire ornaments, lace) can come out with some
  pieces missing (red **Missing parts**). Raise Target Quads or delete the smallest pieces. If a run
  still takes long, press **Esc** to cancel; Blender stays usable.
- **Copy Report** keeps the remesher's output only for the last run since Blender started. Read the
  text before you send it: folder paths outside your home folder are kept as they are.
- **Against 0.2.0 on our test sets** (release check, corpus and closed sets, 6 runs per case on each
  platform, run 41224250346 on `2b858a3`): passed on Linux, Windows and macOS. No structural check
  fails on more cases than with 0.2.0, and no validity number is worse. Changes merged after that
  commit leave the output mesh byte-identical on 770 Linux runs of our test sets, so the check was not
  repeated.
- **Tried by hand on Linux** (Ubuntu 24.04, Blender 4.5, test builds of this release's code): Blender's cube at 2,000 quads with Copy Report (no user name in the
  text), a sword joined from several parts with Sharp on most edges at 3,000 quads (marks left out
  and not copied, no zigzag sharp lines), and Copy Report after a run cancelled with Esc. No crash,
  hang or cut-off text. After a cancelled run, Copy Report shows "0 islands" for the input (not counted
  yet), not the real number. Checked again on the final build: the sword at 10,000
  quads shows Folded faces 39 (24 twisted), matching the report.
- **Tried by hand on Windows** (a real Windows desktop, this release's CI build; build line correct,
  Defender silent, 0 detections on VirusTotal for the download zip): Blender's monkey at 5,000 quads,
  Fast 5,005 quads (1 folded, 0.7 s) and Quality 5,093 quads (0 folded, 1.8 s); a head at 10,000
  quads, 9,854 quads (4 folded, 3 twisted); the cube at 3,000 quads, 2,948 quads (1 folded,
  1 twisted); the sword at 3,000 quads, 2,861 quads (44 folded, 24 twisted). Every result all quads,
  no holes or non-manifold edges. The 300,000-quad warning appears and cancels, Esc cancels a run,
  Ctrl+Z undoes it, and no files are left in %TEMP%. It also passes the automatic tests (the remesher's tests, an
  install into a real Blender 5.2 that remeshes and the panel check). The program is not code-signed
  (see *Download*).
- **macOS is experimental and untested**: nobody has run this release on a real Mac, and the program
  is not notarized, so macOS may block it (user guide §2). Reports from Mac users are welcome.
- Version numbers name releases only. Test builds between releases keep this version; tell them
  apart by the build line.
